# PASS 1 — DRAFT (ARCHITECT-A)

## Project Summary

Graceselle is a single-file static portfolio (`index.html`, plain HTML/CSS/JS, no build tooling) with a dark purple premium aesthetic (`--violet #9d4edd`, Anton display type, JetBrains Mono accents, Inter body, grid-line hero background, horizontal project scroller, reveal-on-scroll). The refresh has three goals: (1) raise the overall UI/UX quality, (2) introduce a REALISTIC hero portrait on the right side of the hero section using `image.png` (3000×4000, 3:4, ~7.5 MB — must be optimized to an ~1000px-wide, <500 KB copy), and (3) document UI/UX improvement suggestions. Deliverable stays a single `index.html` with inline CSS/JS that opens directly in a browser via `file://`; an `assets/` folder for the optimized image is acceptable. No npm, no build step.

## Target Platform(s)

- Desktop-first web (Chrome/Edge/Firefox/Safari, latest 2 versions).
- Mobile web (≤640px) must not lose functionality — currently nav links are hidden there with no replacement, which is a known defect.
- Must work as a static file opened directly in a browser (`file://`), so no CORS, no modules, no external assets beyond Google Fonts.

## Core Features (MVP)

- [ ] 2-column hero: text left (~55%), realistic photo right (~45%), responsive stack on mobile (photo below text).
- [ ] Optimized hero image at `assets/hero-graceselle.jpg` — ~1000px wide, 3:4 ratio (≈1000×1333), <500 KB, `fetchpriority="high"`, explicit `width`/`height` to prevent CLS.
- [ ] Realistic photo treatment: rounded frame (radius ~20–24px), soft violet glow, gradient overlay, drop shadow, decorative floating elements (e.g., badge chips / mono captions), subtle hover scale.
- [ ] Hero CTAs: primary "View my work" (→ `#work`) + secondary "Say hi" (→ `mailto:hello@graceselle.dev`).
- [ ] Fix nav casing/typo: "HOme" → "Home"; consistent link casing per existing mono-uppercase style.
- [ ] Mobile nav: hamburger toggle at ≤640px replacing the `display:none` pattern; menu closes on link click.
- [ ] Project thumbnails: replace gradient blocks labeled `PROJECT_01.PNG` with CSS-drawn mini browser-window mockups (fake dashboard UI per project, 4 distinct layouts).
- [ ] Keep reveal-on-scroll and `prefers-reduced-motion` handling intact.
- [ ] Accessibility: skip-to-content link, `aria-label` on nav/landmarks, `alt` on hero image, semantic landmarks (`header/nav/main/section/footer`), `aria-expanded` on hamburger.

## Suggested Tech Stack

Match the repo — **zero tooling**:

- Language: plain HTML5 + CSS3 (custom properties, grid, clamp(), scroll-snap) + vanilla JS (IntersectionObserver only).
- Fonts: Google Fonts (Anton, JetBrains Mono, Inter) — already linked; keep preconnect.
- Assets: `assets/hero-graceselle.jpg` (JPEG q≈78, 1000×1333) — generated once via Windows PowerShell `System.Drawing` (available in PS 5.1, no install) or any local image tool; **not** committed as the 7.5 MB original. The original `image.png` stays at repo root and is referenced by the spec as the source.
- Hosting: none (file://), optionally GitHub Pages later — no config needed.
- Explicitly avoided: npm, bundlers, frameworks, external JS libraries.

## Suggested UX/UI direction

- **Design system (extend `:root`):** keep the existing tokens; add `--glow: rgba(157,78,221,.35)`, `--frame: #1d1a24` (photo border), `--ok: #4ade80` (status dots in mockups). Consistent radii: cards 18px, hero frame 22px, pills 100px.
- **Hero grid:** `display:grid; grid-template-columns:55% 45%; align-items:center; gap:clamp(24px,4vw,64px)`. Text column keeps eyebrow, name, role, one-line bio, CTAs; right column gets the framed portrait.
- **Typography:** on desktop the name currently scales to 200px — shrink the cap (e.g., `clamp(48px, 8vw, 128px)`) so text and photo coexist without collisions; keep the gradient-clipped Anton treatment.
- **Photo treatment:** rounded frame, `border:1px solid rgba(157,78,221,.35)`, `box-shadow: 0 30px 80px rgba(0,0,0,.55), 0 0 60px var(--glow)`, gradient overlay at the bottom for legibility of a floating mono caption chip, and 1–2 floating decorative elements (small glass pills: "10+ years shipping" / "Remote-first"), one slightly overlapping the frame edge.
- **Mobile (≤640px):** photo stacks below text, reduced name size, hamburger opens a full-screen violet-tinted overlay menu (mono uppercase links, current header `mix-blend-mode:difference` preserved on desktop, disabled in overlay).
- **Mockup thumbs:** each `.thumb` becomes a mini browser window — top bar (3 dots + URL pill) + a tiny dashboard (sidebar, chart bars, stat cards) built purely with divs/gradients, tinted per project's gradient pair. ~230px tall as today.
- **Spacing:** hero min-height stays 100svh; CTAs sit in the hero-foot area; scroll-cue gains a subtle vertical line + arrow refinement.
- **Motion:** respect existing reveal pattern (`.reveal` → `.in`); new animations (hover lift, menu slide) must be disabled under `prefers-reduced-motion`.

# PASS 2 — FINALIZED (ARCHITECT-B)

## Critique of the Draft

The draft is sound and matches the repo's constraints (single file, no tooling). Gaps found and fixed here:

1. **Image budget unproven.** "q≈78 <500 KB" is a guess. Resolution: commit to 1000×1333 JPEG at quality 75–80 as the *budget*, with an explicit fallback to 900px wide / q70 if >500 KB; if both fail, accept 900px PNG only as last resort. Tool: PowerShell `System.Drawing` (`Get-ChildItem` + `Graphics.DrawImage`), a one-off script is fine — it does not violate "no npm/build tooling" (it is a build step, not app tooling, and does not run at page-load).
2. **Name size collision under-specified.** 8vw at 1280px ≈ 102px — safe beside a ~500px photo. Set `clamp(44px, 9vw, 128px)`; hero line-height `.86` retained. Confirmed.
3. **Hamburger detail missing.** Resolved: full-screen overlay (not dropdown) for ≤640px; toggle keeps `aria-expanded` + `aria-controls`; menu closes on link click and on `Esc`; `mix-blend-mode:difference` is disabled on the fixed header while the overlay is open (difference against a fully violet overlay looks broken).
4. **Mockup distinctness.** The 4 thumbs should each show a *different* fake UI (1: analytics dashboard w/ bar chart; 2: monitoring w/ line graph + status pills; 3: invoicing w/ table rows; 4: mobile-app frame w/ list). Pure CSS (gradients + divs) — no SVG, keeps thumbnails lightweight and theme-consistent.
5. **Footer placeholders.** Keep the row (removing it shrinks the contact section visually), keep `href="#"` (no real URLs exist), add `aria-label` like `"GitHub (coming soon)"` — no visible "placeholder" text, it would look unfinished.
6. **Decorative ring.** Resolved: skip a ring/arch (adds risk of cheap look); instead use a floating glass badge overlapping the top-right frame corner + one mono caption chip at bottom-left. Simpler, premium.
7. **Grid background.** Keep the `mask-image` grid behind the photo column — it reads as depth, not clutter, and the photo frame's border + shadow separates it cleanly.
8. **Original image fate.** Keep `image.png` at repo root (do not delete — it is the source of truth and the user placed it there); the optimized copy lives at `assets/hero-graceselle.jpg`. The first commit may note the original is intentionally un-optimized. Optional final follow-up: delete the original in a dedicated commit *only* if the user asks.

Additional fixes not in the draft:

- The nav `.cta` ("say hi") and new hero "Say hi" both target the mailto — fine, but hero CTA set must be visually ordered (primary filled violet pill = "View my work"; secondary ghost = "Say hi").
- `skip-link` must be the first element in `<body>`, visually hidden until `:focus-visible`.
- Header currently uses `mix-blend-mode:difference` — with the new photo column this stays okay (photo sits below header z-index area only at scroll), confirmed no conflict since header is fixed and photo scrolls under it; ensure header has a solid fallback for browsers without blend support (transparent → subtle `rgba(10,10,13,.6)` backdrop on scroll).
- Hero photo needs `decoding="async"` + `fetchpriority="high"` + `width="1000" height="1333"`.
- The scroller drag code should not hijack text selection — existing code is fine but add `cursor:grab`/`grabbing` state classes.
